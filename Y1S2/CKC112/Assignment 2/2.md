# CKC112 Assignment 2: Mini File System Explorer — Student 3 Contribution

## 📌 Module Overview
As Student 3, I was solely responsible for the Navigation and Robustness Module. My primary focus was establishing a safe, exception-guaranteed runtime environment, handling folder-to-folder traversal state transitions via active pointer manipulation, and building the terminal user interface.

---

## 🛠️ Core Functional Implementations

### 1. Pointer-Based Folder Navigation
I implemented directory traversal tracking by utilizing the parent and subfolders vector pointers within the Folder configuration:
- **FileSystem::enterFolder()**: Validates user inputs and scans the subfolder vector array matching the directory string. If matching references exist, the state pointer (currentFolder) updates to step into that subdirectory space.
- **FileSystem::goBackToParent()**: Moves the navigation pointer up one level using the current node's getParent() reference.

### 2. Comprehensive Exception Handling & Robustness
To fulfill the explicit robustness requirements, I engineered custom runtime protection barriers using try-catch blocks across all interactive menu input methods to ensure the simulator never crashes from invalid user data:
- **Boundary Fault Interception**: Handled navigation errors by explicitly throwing exceptions if a user attempts to enter a non-existent folder, or trigger a back-traversal (goBackToParent) while already positioned inside the system Root.
- **Destructive Deletion Warnings**: Wrapped the asset cleanup tasks (deleteFile and deleteFolder) in validation routines to trap cases where a user tries to drop invalid reference titles.
- **Type-Safe Sanitization**: Implemented menu choice evaluations to prevent endless loop hangs if string text payloads are fed into standard integer choices (cin stream recovery).

### 3. Absolute Path Generation
- **FileSystem::getCurrentPath()**: Designed a backward-climbing traversal method. Starting from the active pointer context, it scales sequentially through upstream getParent() pointers up to the base layout terminal node to dynamically output a clean string representation of the current working directory (e.g., Root/Courses/OOP).

### 4. Application UI Interface Engine & Integration
- **FileSystem::runMenu()**: Developed the central interactive console engine containing the exact 11-option menu schema required by the specification. 
- This menu acts as the primary orchestrator that routes inputs to Student 1's deep recursive functions and Student 2's storage container routines.
